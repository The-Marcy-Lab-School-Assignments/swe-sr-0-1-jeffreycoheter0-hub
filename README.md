## Prompt 1

A good technical explanation often uses a metaphor to help others understand a complex concept. Choose a metaphor to represent a Git commit. 

In a few brief paragraphs, use your chosen metaphor to explain:
* What a commit is
* How a commit is created (include the command-line syntax)
* Why commits are useful in version control.
* Why it is important to write descriptive clear messages in team settings.

### Response 1
* A commit is like adding a bookmark to a book. You always place it in the book to let your self know where you left off at. And could also be a way to bookmark notes. For example, when you find something interesting in the book you can leave a note adding a comment to explain why you bookmarked it.
* The commit command-line syntax is usually "git commit -m '' ". The commit -m stages all the changes that were changed in that file. Stages basically means dressing up the code and it allows you to express yourself, explaining why you wore a certain item that day. 
* Commits are super reliable and understandable. You can always look back at your commits to see why you did a change or when you completed something. Basically documenting your code. When working with a team you will usually branch out to different branches in a file. Commiting allows the contributers to add their own changes without disturbing the main file code. And when they commit you can see their comment on why or what changes they added, making it easy to identify changes you want to merge into the main file. 
* Going back to the previous answer, writing descriptive clear messages makes it easier for the team to identify the changes made in said branch file. They can then dtermine whether or not they want to merge the code with the main file.
